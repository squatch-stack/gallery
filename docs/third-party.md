# Third-party software vetting

Before installing Blender, an add-on, or an MCP server on the owner's Mac:

1. Pin an exact release version or source commit; `unpinned` is an unresolved gap.
2. Compare the downloaded bytes against a checksum from the publisher's own
   artefact/checksum publication. Keep that evidence in `--note`.
3. Read the LICENCE/LICENSE from the downloaded artefact, not a web page, and
   record its SPDX identifier. `UNKNOWN` requires a reason and follow-up.
4. Read an add-on's source before enabling it. Record the review and any required
   integration restrictions in notes.

The registry is evidence, not installation approval. Hashing establishes a
baseline; it does not prove publisher authenticity, licence review, or safety.
The tool never installs, extracts, imports, or executes downloaded code. It uses
stdlib HTTPS, refuses insecure redirects, and deletes its temporary downloads.
Only `record` writes `third-party.json`; `verify` and `list` are read-only.

## Commands

Run from the repository root:

```sh
python tools/vet_download.py record https://publisher.example/addon-1.2.zip --name addon --version 1.2 --licence MIT --note 'LICENSE and source reviewed; publisher checksum matched'
python tools/vet_download.py record --file ~/Downloads/addon-1.2.zip --name addon --version 1.2 --licence UNKNOWN --note 'Downloaded LICENSE still needs review'
python tools/vet_download.py verify
python tools/vet_download.py verify --name addon
python tools/vet_download.py verify --offline
python tools/vet_download.py verify --name addon --file ~/Downloads/addon-1.2.zip
python tools/vet_download.py list
python tools/vet_download.py list --json
```

`record --file` may also include the HTTPS URL. Local paths are stored relative
to the repository; moving the artefact/repository can break that reference.
Verification prefers the recorded local file, otherwise downloads the URL;
`--file` overrides the source for the named records. Offline mode skips entries
without a recorded local path, even with an override. Missing files, unknown
hashes, download errors, and mismatches fail with exit 1 and identify the entry.
A run that skips everything reports zero verified entries, not proof of safety.
All versions, including superseded records, are checked. Recording a new version
retains earlier entries and marks the previous active versions `superseded_by`.

To import supplied evidence without reading bytes, use:

```sh
python tools/vet_download.py record https://publisher.example/addon-1.2.zip --name addon --version 1.2 --licence MIT --no-fetch --sha256 UNKNOWN --size UNKNOWN --date-checked 2026-09-04 --note 'Evidence imported; download and publisher checksum review pending'
```

`--no-fetch` requires an explicit SHA-256 (64 hex digits or `UNKNOWN`), byte size
(nonnegative integer or `UNKNOWN`), and ISO review date. Unknown values become
JSON `null`; every imported entry is `unverified` with `verified_at: null`, even
when a supplied hash exists. Normal recording computes hash, size, and today's
date and marks `hashed`; this still does not attest to the four manual reviews.
`date_checked` is the recording/review date and is not changed by `verify`.
